# ADR-001: 手写 Win32 FFI 而非引入第三方 crate

## 状态：已采纳

## 背景
WallpaperRust 需要调用 Windows 系统 API：WinHTTP 下载、SystemParametersInfoW 设置壁纸、COM IPicture 加载图片、注册表写入锁屏 CSP、ShellExecuteW 提权、窗口创建与消息循环。

常规做法是引入 `windows-rs` crate（微软官方维护的 Win32 绑定）或 `winapi` crate。两者都成熟可靠。

## 决策
**手写 extern "system" FFI 声明**，不引入任何第三方 crate。所有声明集中在 `win32/mod.rs` 的 `unsafe extern "system"` 块中。上层业务代码不直接写 unsafe 系统调用。

## 后果

好：
- 产物合计约 300 KB（DesktopRust 145 KB + LockscreenRust 154 KB），引入 windows-rs 会至少翻倍
- 供应链零风险，无需监控 crate 生态的漏洞和断更
- FFI 声明与项目实际使用一一对应，不存在未使用的符号膨胀

坏：
- 手写声明无编译器校验 Windows SDK 版本兼容性，系统 API 签名变更时可能静默崩溃（极低概率，Win32 API 稳定）
- 维护成本更高：新增系统调用时需要手写类型和常量
- COM vtable 布局（IPicture）完全靠手动维护，一旦 Win32 结构定义与手写不一致会崩溃

## 替代方案

| 方案 | 放弃理由 |
|---|---|
| `windows-rs` crate | 依赖体积大（~数 MB 传递依赖），与"双击即换、单文件小工具"的定位冲突 |
| `winapi` crate | 虽轻量但维护状态不佳，2023 年后基本停止更新 |
| 条件编译跨平台 | 项目明确只做 Windows，跨平台代码无意义 |
