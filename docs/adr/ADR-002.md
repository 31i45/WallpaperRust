# ADR-002: 桌面与锁屏拆为两个独立 exe

## 状态：已采纳

## 背景
桌面壁纸和锁屏壁纸功能高度相似（下载图片、设为壁纸），常规做法是合并为一个程序，通过命令行参数或 UI 选择"换桌面"还是"换锁屏"。

但两个功能有一个本质差异：**锁屏壁纸需要管理员权限**（写 HKLM\PersonalizationCSP 和 %ProgramData%），而桌面壁纸在普通用户权限下即可完成。

## 决策
拆为两个独立二进制：
- `DesktopRust.exe` — 普通用户权限，双击即换桌面，静默退出
- `LockscreenRust.exe` — 自动提权（ShellExecuteW runas），预览后设锁屏，退出

## 后果

好：
- **不打扰普通用户**：DesktopRust 双击直接执行，不触发 UAC；锁屏用户才会看到提权弹窗
- **体积隔离**：DesktopRust 不包含预览窗口和 COM 加载代码（约节省 9 KB）
- **权限模型清晰**：不需要一个"有时提权有时不提权"的中间态——要么完全有权，要么完全没有
- **交互极简**：桌面版无窗口无弹窗，符合"双击即换"的一次性工具定位

坏：
- 两个 exe 需要分别构建和分发（但 release profile 配置已统一，实际只需 `cargo build --release` 一次）
- 共享库代码（下载、校验、图源、壁纸设置）必须通过 crate lib 复用，不能在两个 main 中复制粘贴

## 替代方案

| 方案 | 放弃理由 |
|---|---|
| 合并为一个 exe + 命令行参数 | 桌面用户会被触发 UAC，体验极差 |
| 合并为一个 exe + 动态提权 | ShellExecuteW 会启动新进程，状态同步和退出清理复杂；且普通用户双击后先等 UAC 再等下载，延迟叠加 |
| 常驻托盘后台，定时/事件触发 | 违背"换壁纸是一次性动作"的设计哲学；原版 Python 实现常驻 14MB 内存不退出，重构动机之一就是摆脱常驻 |
